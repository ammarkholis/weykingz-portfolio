01 · Industry 4.0 · IoT

Real-Time Machine Monitoring

My role: built the whole software side — MQTT broker, subscriber, database, dashboard and alerts — on ESP32 hardware provided by maintenance.

Context

The maintenance team checked machine status by walking the floor or waiting for someone to report a stop. There was no history and no way to see downtime per machine.

What I built

ESP32 devices wired to each machine's power and process signals publish every status change over MQTT. A Node.js subscriber stores the history in MySQL, and a responsive dashboard shows live status, logs and daily recaps — on phones, laptops and the TV in the monitoring room — with Telegram notifications to the maintenance group.

Outcome

Status changes are visible within seconds, and the team uses it daily. When the daily recap drifted, I rebuilt it to recompute from the raw event log and backfilled 7 months of history.

02 · Monitoring · NOC

Multi-Site ISP & Server Monitoring

My role: designed and set up the monitoring server, dashboards and alert rules end to end.

Context

When the internet went down at a plant, IT usually heard it from users first. Nobody could say which ISP failed, when, or for how long — so SLA claims with providers were guesswork.

What I built

A central NOC on Zabbix + Grafana: live bandwidth and up/down status for every ISP link at every site, plus Hyper-V hosts, VMs, firewalls and routers. Alerts go to separate Server and Network Telegram channels with severity filters, and the team gets a read-only dashboard.

Outcome

Outages are known before users call, every down/recovery is timestamped for provider follow-up, and alert noise dropped once channels and filters were split.

Zabbix 7GrafanaSNMPTelegramLinux

03 · Power Platform

BAST IT — Asset Handover App

My role: gathered requirements, wrote the functional document, built the app, trained users and supported go-live.

Context

Every laptop or PC handed to an employee needed a paper handover form (BAST). Forms got lost, and nobody could quickly answer "who holds this device?"

What I built

A Power Apps app on SharePoint lists: register assets with auto-generated codes, create a BAST with digital sign-off, and generate the handover document automatically. The current holder updates itself on every handover.

Outcome

Paper forms eliminated for IT handovers, a complete history per device, and asset lookups that take seconds instead of digging through folders.

Power AppsPower AutomateSharePoint

04 · Backup & Disaster Recovery

On-Prem Backup & DR Platform

My role: designed the backup architecture, built the server and automated the daily backup jobs.

Context

The ERP system's disaster recovery ran on a cloud service that was costly and had never been tested. The company decided to stop it — which meant the ERP needed a new safety net.

What I built

A self-hosted S3-compatible backup server on repurposed hardware, receiving SQL backups automatically every day with 30-day retention. Next phase is designed: an immutable Veeam repository for the Hyper-V VMs and offsite copies to a secondary server in Jakarta.

Outcome

About 15 GB of SQL backups per day land on-prem automatically, the recurring cloud bill went to zero, and unused cloud resources were cleanly decommissioned.

05 · Web App · Microsoft 365

QR Document Portal — AWS to SharePoint

My role: led the storage migration and brought the portal back online after the server move.

Context

Customers scan a QR code on the product to download its quality documents, which the QC team uploads as PDFs. Storage sat on AWS S3 — an extra bill and a place QC couldn't manage themselves. A hosting migration later took the portal offline.

What I built

Moved document storage to SharePoint on the existing Microsoft 365 license. After the move to a new cPanel VPS, fixed internal DNS, restored missing Composer dependencies and patched the legacy code for PHP 8.1.

Outcome

One less cloud bill, QC manages files in a tool they already use, and the portal is back online on the new server.

Troubleshooting stories — 6 short problem → cause → fix write-ups
Firewall rules that never blocked anything
The rules referenced an address list that didn't exist, and FastTrack skipped inspection anyway. Rebuilt as one re-importable script above FastTrack and verified with hit counters.
Subdomains down after a hosting migration
Internal DNS still pointed to the old server, vendor/ wasn't carried over, and the new server's minimum PHP was 8.1. Fixed all three; both portals came back.
The controller that couldn't be turned off
The new UniFi VM actually ran on the old controller PC, which also served file shares. Kept the host and redirected APs with an inform-host override instead.
39 birthdays silently swapped by Excel
None of the converted dates had a day above 12 — statistically impossible. Imported the column as text and reported the rows to HR.
UPS monitoring on a hypervisor without USB passthrough
Hyper-V can't pass USB to guests, so NUT runs on the physical host (firewalled) and the dashboard runs as a systemd service on Linux.
Alert fatigue in the NOC
One channel got every alert. Split Server and Network channels, added severity filters and excluded known-noisy services.
